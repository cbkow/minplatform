### Step 1 in brief (rows 228–233)
`qcv-ring` (the frozen contracts: QCAE frames, QCAA audio, QCVO output; byte-exact against the vendored C++), `qcv-player::
host_feed` (QCView's HostBridgeSource) and `audio::live` (LiveAudioSource; a non-48 kHz host resampled), the live row
(`live_strip.rs`, replacing strip / transport / scrubber), LIVE / REVIEW (Space freezes the FLOAT frame — `Engine::hold_shown`),
stream notes byte-for-byte QCView's (`<project>/.qcview/streams/<name>__<id8>/`), the Inspector's live cards. Seven QCView bugs
fixed (row 228). Auto transfer label for a host feed = "Auto · working space, untagged" (row 230). Listen lives on the live
row only (row 231).

### Step 2 in brief (rows 234–236)
`min-ffmpeg`'s live mode (low-delay demux, interrupt flag, timed packet reads) + `qcv-player::stream_feed` (QCView's
LiveStreamDecoder: drain-to-edge / wait-keyframe / streaming, 250 ms → 3 s backoff). `apps/qcv/src/blender.rs` watches the
card (`QCView/Inputs/blender.json`) while File ▸ Connect to Blender is on (off every launch). A stream's Auto label follows its
tags (QCView's rule: "Auto · PQ 2020" for the Blender wire). The passphrase is redacted everywhere it is shown or logged.

### Step 3 in brief (row 237)
No SDK in QCView: per output a QCVO frame ring + a QCAA audio ring; the sink apps are found by manifest
(`QCView/Outputs/*.json`) and launched on switch-on. `Engine::render_output` (composite or one dual side, letterboxed, LINEAR)
→ `min_present::wire::WireEncoder` (BGRA8 / RGB10; SDR · PQ Rec.2020 or P3 · HLG) → the ring, publish-on-change. The Output
section (`output_panel.rs`) is the port's design: a card per sink, status dot, on/off switch, recessed controls, the feed
muted by default.

**Layers (row 238, reversing row 225):** the safety guide and the note's strokes go out as QCView sent them — the sink's
request ∧ the two header toggles (Guides, Notes; both on); strokes only while the viewport draws them (Notes panel open,
single view); 203 nits on PQ = 75 % on HLG; the guide's line keeps the viewport's proportion (the port's rule, screenshots
too). A vello overlay at the raster, laid over the canvas by the wire encoder.

## Build and run

- **Walk on the RELEASE build** (`cargo build --release -p qcv`; `target/release/QCView`). The debug build's per-pixel loops
  misled two walks (13-fps "1080p", slow note images).
- **FFmpeg** is the family's patched 9.0.2 (QCView's three patches), built per OS by `tools/ffmpeg/` — macOS
  `build-macos.sh` (+ static libsrt / mbedTLS for SRT), Windows `build-win64-wsl.sh` (BtbN's recipe in WSL2). `.cargo/config.toml`
  puts the macOS build ahead of Homebrew's. **The `ffmpeg` on PATH is Homebrew's** — never judge the app's FFmpeg by it
  (`external/ffmpeg/macos-arm64/bin/ffmpeg` is ours).
- **Windows DX12** uses the pinned `dxcompiler.dll` (`tools/dxc/`), found beside `QCView.exe` or in `external/dxc/win64`.
- Windows builds need the vcpkg dirs in the environment: `OPENEXR_DIR` / `TURBOJPEG_DIR` / `TIFF_DIR` / `OCIO_ROOT` = the
  vcpkg `installed/x64-windows`, its `bin` + `tools/tiff` + the FFmpeg `bin` on `PATH`, `LIBCLANG_PATH`, `FFMPEG_DIR`.
- On Windows a QCAE ring lives in the `Local\` namespace, which is **per session**: a producer started over SSH is invisible
  to an app on the desktop — launch both in the desktop session (a one-shot scheduled task with `/it`).

| A real-PQ SRT sender | Homebrew `ffmpeg` + `lutrgb` with the PQ curve (an SDR pattern merely TAGGED PQ washes out — that is the signal, not the decoder), x265 Main10 with the PQ / BT.2020 VUI, piped into our FFmpeg for the `srt://` leg. |
| A Blender card | `blender.json` with `kind: "blender"` and `url: srt://0.0.0.0:9998?mode=listener…` in `$QCV_INPUTS_DIR`. |

Isolation for a test run (nothing of the user's touched): `QCV_SETTINGS_DIR` (a throwaway store), `QCV_OUTPUT_MANIFEST_DIR`
(test manifests win over the installed ones — first registration wins), `QCV_INPUTS_DIR`, `QCV_MULTI_INSTANCE=1` (no hand-off
to a running window).
